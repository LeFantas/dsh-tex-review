# tex-review · 论文审查与批复闭环

这个 skill 只做两件事：

- **A 审查**：对指定 `.tex` 做 n 次独立审查，按类别和等级汇总，写出带 `RE：` 的审查 md。
- **B 批复**：读取审查 md 里的 `RE`，按 `xg` / `tg` 修改论文，按 `ED` 回复并留新的 `RE`，把结档条目移入日志 md。

不审查用户没指定的论文；不顺手改与条目无关的内容。

## 1. 输入

```text
/tex-review <论文.tex> [n=<次数>] [s=<类型>] [--out <报告路径>]
/tex-review <审查.md>          # 进入批复模式
```

- `n` 不写时默认 1（单次审查）；建议 3。**不要因为没给 n 就追问**，直接按默认跑，并在报告头部注明。
- `s=` 是审查类型（scope），简称：`T`=文字性，`M`=表意，`S`=结构，`C`=cite。缺省 `all`（四项全做），并在报告头部注明“未指定，按完全审查执行”。
- 组合：`s=T,M`、连写 `s=TM`；`s=all` / `s=全` 等价；也接受中文全名 `s=文字,结构`。类型不区分大小写。
- 注意 `s=` 是参数名、`S` 是结构简称；`s=S` 就是只查结构。
- 论文由 `\input` / `\include` 组成时先展开；`位置` 一律带文件名：`` `sec/intro.tex` L12–L14 ``。
- 默认产物（论文同目录）：
  - 审查报告：`reviews/<stem>-review-<YYYYMMDD-HHMM>.md`
  - 结档日志：`reviews/<stem>-review-log.md`
  - 备份：`reviews/backups/<stem>-<YYYYMMDD-HHMMSS>/`

开工前先完整读一遍主文件，确认行数和结构；不要凭文件名猜内容。

## 2. 审查维度

类型简称：`T`=文字性，`M`=表意，`S`=结构，`C`=cite；命令里的 `s=` 用这套简称。

### 2.1 文字性（T）

只查文字正确性，不做改写、不评风格：

- 语法：主谓一致、时态、动词形式、比较级、介词搭配、平行结构、残句/逗号粘连、悬垂修饰。
- 拼写：拼写错误、错词、大小写；同一篇内英式/美式拼写不一致。
- 冠词：a / an / the / 零冠词；可数与不可数（如 `literature` 作“文献”讲不可数）。
- 从句：that / which、关系从句、从句语序、从句与主句的逻辑衔接。
- 标点：逗号、分号、冒号、破折号/连字符、撇号、引号、括号，以及与行内公式相邻的标点。

不查：句子是否优美、术语选择、观点是否正确。一句话里有多个独立错误时拆成多条。

### 2.2 表意（M）

- 读起来是否通顺：是否需要回读才能懂。
- 是否有歧义：代词 `this/it/they` 指代不明；否定/量词辖域；修饰语附着；比较对象缺失；`and/or` 范围不清；`respectively` 对应错位。
- 逻辑连接是否正确：`however/therefore/moreover` 与前后文关系是否一致。

不查：语法错误（归 T）、符号定义（归 S）。改写必须保持作者原意；原意无法确定时在“问题”里写明假设。

### 2.3 结构（S）

- 缩写/首字母词：是否在**第一次**出现时定义；后续是否重复定义；是否先用后定义；定义后是否一直使用；同一缩写是否指代两个东西。
- 符号：数学符号是否在首次使用处（正文或公式前）定义；同一对象是否始终用同一符号；是否有未定义符号、重定义、记号冲突。
- 交叉引用：每个 `\ref` / `\eqref` / `\autoref` / `\cref` / `\Cref` 是否有对应 `\label`；`\label` 是否重复；引用类型是否匹配（figure/table/section/equation）；正文写死的 “Section 3” 是否指向正确目标；图表/公式是否被正确引用。

不查：`\cite` 系列（归 C）、文字表达（归 T/M）。`\newcommand` 只作为符号线索，不要求正文逐一解释宏。

### 2.4 cite（C）

先读 preamble，确认是 natbib、biblatex 还是期刊模板自定义，再判断：

- 命令语义：natbib 下 `\citet` = 文本式 “Jones et al. (1990)”，`\citep` = 括号式 “(Jones et al., 1990)”，`\cite` 与 `\citet` 同义；biblatex 下 `\textcite` / `\parencite` / `\cite` 按样式。不要把括号式命令放进已有括号，不要在句首用括号式命令，不要出现 “Jones \citep{...}” 这类作者名重复。
- 标点与位置：句末引用放在句号前；多个 key 的顺序与分隔；可选项 `[see][p.~3]` 是否落在正确位置；`\citet` 作主语时谓语与作者数一致。
- bib 完整性：每个 cite key 在 bib 中存在；没有重复 key；条目类型与必需字段完整；没有未被引用的条目（或注明有意列出）；同一文献没有重复条目；DOI/页码/卷期格式正确。
- 条目正确性：作者、年份、标题、期刊/会议、卷期页码与正式出版信息一致；arXiv 预印本是否已有正式版本。**允许联网核验**：用 DOI、Crossref、出版社页面、DBLP、arXiv 对照，把核验 URL 写进 `**证据**`；核验不了写“未核验”，不得编造。

不查：引用在学术上是否恰当、是否漏引某篇文献（属于内容判断）。

## 3. 模式 A：审查

### 3.1 准备

1. 展开 `\input` / `\include`，得到文件清单与每个文件的行数；确认主文件。
2. 读 preamble：文档类、natbib/biblatex、自定义 cite 宏、定理环境、`\newcommand`。
3. 找 bib 文件（`\bibliography{}` / `\addbibresource{}`），确认 key 集合。
4. 建 `reviews/` 和 `reviews/.runs/<YYYYMMDD-HHMMSS>/`；不要修改任何源文件。

### 3.2 n 次独立审查

用 `subagent` 一次并行派出 n 个审查员；每个审查员只拿到：论文路径、维度、输出 schema、本遍的 `pass-k.json` 路径，**不告知其他审查员的结果，也不告知主代理的猜测**。提示词直接使用 `templates/reviewer-prompt.md` 填充。

- 每遍分配 `reviews/.runs/<时间戳>/pass-<k>.json`；`{{OUTPUT_PATH}}` 填这个绝对路径。
- 子代理只允许写这个 JSON 文件，不得改论文或其他文件；完整 findings 写入文件，最终答复只回 `WROTE <path>`。
- 回收时**先读文件并 `JSON.parse`**，不要拿子代理的最终文字当结果；文件缺失、解析失败、字段不全或只有摘要 → 给同一个子代理发补发消息（“只把完整 JSON 写入原路径，最终回 WROTE”），仍失败就换一个新审查员重跑该遍。
- 子代理没有写文件工具时，才接受最终答复里的完整 JSON；仍按字段校验，摘要不算结果。
- n=1 时只派一个审查员（或做一遍）；报告头部写“n=1（单次）”，不要写“并行”。
- n≥3 时可让各遍采用不同阅读顺序（正序、倒序、按节跳读），减少同一盲点；除此之外提示词保持一致。
- 没有 subagent 工具时，串行做 n 遍：每遍重新读文件、不复用上一遍笔记，并在报告中写“串行”。
- 不要凭空补条目；重跑仍失败就记该遍失败，报告头部写有效份数（如 `n=2（并行；1/2 有效）`）。

### 3.3 合并

- 从各遍的 `pass-k.json` 读取 findings 合并，不依赖子代理的最终文字。
- 聚类键：同一类别 + 行区间重叠（或原文高度相似）+ 同一问题。命中数记为 `k/n`。
- 等级：多数票；平票取高。`n≥2` 且 `k=1` 的条目标“单次命中”，提醒用户低置信。
- 建议：取最清晰、改动最小的版本；两遍给出实质不同的改法时，主建议 + `**备选**：...`。
- 每条都要回读源文件核对 `quote` 和行号；对不上就丢弃，不要“大概在附近”。
- 同一问题跨类别时只保留主类别，在“问题”里注明“另见 X 类”。
- cite 条目合并后统一做一次联网核验（主代理做），把证据补进条目；子代理已核验的保留其 URL。

### 3.4 写报告

按 `templates/review-report.md` 生成，字段一个不能少：

- `**位置**`：文件名 + 行号；多处用逗号列出并写总数。
- `**原文**`：逐字复制，保留 LaTeX；跨行给完整片段。
- `**问题**`：错在哪，一句话说清规则/依据。
- `**建议**`：怎么改；需要时给理由。
- `**修改后**`：可直接替换的完整文本；删除写“（删除）”并在建议里说明范围。
- 需要用户提供信息的条目（如 bib 缺失、方法名不确定）：`**修改后**` 可写 `（待补：...）`，并在建议里注明“需你在下一轮 `RE` 里提供信息，不能直接 xg”。
- `**RE**`：初始留空，只写字段名；用户批复后条目里会出现交替的 `**RE**` / `**ED**` 块（见 4.1），`**修改后**` 始终保存最新提案。
- `**证据**`：cite 条目填写核验 URL 或对照结果；其他条目可省略。
- 报告头部写“独立审查：n=...（并行/串行；k/n 份有效）”；原始 JSON 保留在 `reviews/.runs/<时间戳>/`，便于追溯。

ID 在整篇论文生命周期内唯一：生成前读日志，取各类已用最大编号续编（日志里有 `T-07`，新报告就从 `T-08` 开始）。

排序：`## 文字性审查` → `## 表意审查` → `## 结构审查` → `## cite审查`；类别内 高→中→低，同级按行号。某类无条目写“（无）”。

写完运行：

```bash
node <skill目录>/scripts/review_report.mjs check <报告.md>
```

校验不过就修到通过。

### 3.5 回复用户

只回：

- 条数与等级分布（一句）；
- 报告路径（可点击）；
- 一句批复说明：“在每条 `RE：` 后填 `xg` / `tg`，或直接写你的修改意见；代理会在 `ED：` 下回复并留新的 `RE：`，然后回复‘处理批复’。”

不要把整份报告贴进聊天；不要漏掉 `n` 和 `s`。

### 3.6 条目格式

字段名和顺序固定；用户靠 `RE` 批复，脚本靠这些字段结档。示例：

````markdown
### T-01 · 高 · 命中 3/3

**位置**：`main.tex` L112–L114

**原文**：

```latex
We first review the literatures on multiple testing.
```

**问题**：`literature` 作“文献”讲是不可数名词，不能用复数。

**建议**：改为单数。

**修改后**：

```latex
We first review the literature on multiple testing.
```

**RE**：
````

## 4. 模式 B：处理批复

用户给出审查 md（或说“处理批复”）后：

- 没给报告路径时，在论文目录的 `reviews/` 下找最新的 `*-review-*.md`；有多个候选或不确定是哪篇论文时只问一次。
- 日志优先用报告末尾写的路径；报告没写就用同目录的 `<stem>-review-log.md`。

1. 读报告并运行 `check`；列出最后一个 `RE` 已填的条目。没有已填项就告诉用户还差哪些，结束。
2. 逐条读取**最后一个** `RE`（`RE` / `ED` 可能交替出现多轮）：
   - 去掉空白后**恰好是** `xg`（不区分大小写）→ 按当前 `**修改后**` 修改。
   - 恰好是 `tg` → 不修改。
   - 其他非空内容 → 进入 **ED 回复**：不落盘，写 `**ED**` 回复 + 新建议，更新顶部 `**建议**`/`**修改后**`，再留一个空 `**RE**`，**不结档**。
   - 最后一个 `RE` 为空 → 这条在等用户，跳过。
   - `xg` / `tg` 后只跟“同意 / 可以 / OK / 按建议”之类确认语 → 仍按对应决策；后面跟具体改法 → 按 ED 处理。
3. 本批第一次改文件前做备份：把论文及 bib 复制到 `reviews/backups/<stem>-<时间戳>/`。
4. 按报告顺序处理。每条 xg：
   - 重新读当前文件（前面的修改会让行号偏移）；
   - 在 `**位置**` 指出的文件里用 `**原文**` 全文定位（可能是 `.bib`，不要只改 tex），必须唯一命中；
   - 替换为当前 `**修改后**`（ED 轮次改过就用最新版）；删除类按建议范围删；
   - 校验：旧文不再存在、新文存在且只出现一次；改 bib 时确认所有引用该 key 的地方仍能解析；
   - 失败（0 处 / 多处 / 与其他条目冲突）→ 不结档，在条目加 `**处理备注**`，最后统一问用户。
5. `tg` 直接结档，不动文件。
6. 结档：把条目从报告移入日志，记录批复、时间、修改摘要。优先用脚本：

```bash
node <skill目录>/scripts/review_report.mjs close <报告.md> <日志.md> <ID> xg --note "已替换并核对"
node <skill目录>/scripts/review_report.mjs close <报告.md> <日志.md> <ID> tg
```

脚本不可用时手工移动，规则不变。

7. ED（只回复 + 改提案，不落盘）：
   - 读懂最后一个 `RE` 的意见；同意、澄清或说明为什么不建议照做；
   - 在条目末尾、最后 `RE` 之后写 `**ED**：`，内容是回复 + 新的修改建议；新建议用 fenced code block 展示；
   - 把条目顶部的 `**建议**` / `**修改后**` 更新为最新提案（`xg` 时按它落盘）；
   - 在 `**ED**` 之后再加一个空 `**RE**：`，等下一轮；
   - ED 里的代码块只是展示；要调整请在新增的 `RE` 里说，代理会同步更新顶部 `**修改后**`；
   - 不改 tex/bib，不结档；ED 块里不要再重复 `**修改后**` 字段，避免解析歧义。
8. 全部处理完再回复：修改几条、跳过几条、ED 回复几条待复核、失败/待确认几条、剩余待批复数、备份与日志路径。结档后若“优先处理（当前）”里列了已结档条目，顺手刷新为剩余高优先级条目。

### 4.1 批复格式

`RE` 后可以是决策，也可以是一轮意见：

```text
xg
```

```text
tg
```

一轮意见会形成 `RE` / `ED` 交替的讨论，条目最后始终留一个空 `RE`：

````markdown
**RE**：用 `the method` 是不是更自然？行的话就按这个改。

**ED**：可以，但上一句还没有点名具体方法；我建议保留 `the procedure`，或在 L9 先补方法名。若你只想改这里，最新建议是：

```latex
This is important because the method controls the error rate.
```

**RE**：
````

- `xg`：按条目顶部当前的 `**修改后**` 落盘（即 ED 的最新提案），然后结档。
- `tg`：直接结档，不碰文件。
- 新一轮 `RE`：继续 ED，不落盘。
- 多个 `xg` / `tg` 可以一次批复多条；用户明确说“全部 xg”时才批量通过，并逐条记录。
- `RE` 也可以写在聊天里（如 “T-01 xg”），处理前先写回条目，保证报告是唯一事实源。

### 4.2 定位与冲突

- 行号只是报告生成时的坐标；一律用原文匹配，不按行号硬改。
- 一处原文出现多次：用相邻上下文和行号缩小范围；仍不唯一就停下来问。
- 0 处命中：先检查 `**修改后**` 是否已经在文中（可能之前已应用）；是则按已应用结档，否则报失败。
- 两条修改落在同一片段：先应用一条并复核，再处理第二条；冲突就停第二条并说明。
- 结档后不回头改已结档条目；要返工就把它从日志复制回报告并给新 ID，或在日志追加“重开”记录。
- ED 不落盘，所以不存在“ED 后 tg 要回滚”；tg 只是拒绝当前提案并结档。若某条已经 xg 结档，之后要返工，按上一条处理。

## 5. 结档日志

日志按时间追加，不删除历史；每条至少含：ID、类别、等级、批复（xg/tg）、结档时间、位置、原文、建议、修改后（最新提案）、RE/ED 讨论记录（如有）、备注。脚本按 `templates/review-log.md` 生成。

报告头部两行由脚本维护，格式不要改：

```markdown
- 当前待批复：N 条（高 h / 中 m / 低 l）
- 已结档：K 条
```

`K` 是本论文日志累计条数。

## 6. 红线

- 不虚构：每条必须能回读原文；cite 证据必须真实可访问。核对不上就不写。
- 最小改动：只动条目覆盖的文本；不改写无关句子、不重排格式、不动 preamble（除非条目就是它）。
- 不替作者改观点、数据、结论。
- 每次写前读当前文件；不用行号硬定位，用原文。
- `tg` 绝不改；`xg` 只按当前 `修改后` 改；`ED` 只写回复和新提案，不落盘。
- 无法唯一定位、批复含糊、两条修改冲突 → 停下来问，不猜。
- 报告/日志用 UTF-8；LaTeX 命令、花括号、转义符原样保留。
- 结档是移动，不是删除；日志是唯一历史。
